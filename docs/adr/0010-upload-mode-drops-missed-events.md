# 上传模式关闭期间错过的单次事件不补发

0x0F 关闭上传模式后，从机不发送事件类主动上报：结果事件 0x0A、0x0E 和故障主动上报 0x11。心跳 0x10 与等待握手期间的握手上报 0x01 照常发送。规范 5.2.15 只写了「关闭后主机仍可用获取类命令查询」，没有写再次开启时要不要补发关闭期间才就绪的那一帧。

决定不补发。结果仍留在从机里，主机用 0x09、0x0D、0x12 读到。再次把上传模式设为开启，也不把错过的那一帧补发出去。握手把模式设回上电初值（经常是开启）时同样不补发。仅因发送 FIFO 已满而还没发出的帧，握手之后照常发出。

这和低功耗相反。低功耗是把已经就绪的主动上报压住，退出后再发。上传模式是主机声明自己不要这些事件帧。

## Considered Options

- **压住，再次开启后补发**（与低功耗同一做法）：主机可能已经用获取命令读过结果，补发的事件变成第二次通知。否决。
- **连查询结果一起丢掉**：主机无法闭环。违反 5.2.15「关闭后仍可用获取类命令查询」。否决。
- **不发送、不补发，查询仍可读**：上面这条决定。

## Consequences

- 规范 5.2.15 要补上「关闭期间错过的单次事件不补发」，并写明从机再次接受握手请求时，上传模式回到产品配置的上电初值。
- 用 0x0B 退出低功耗时，若上传模式仍是关闭，被低功耗压住的 0x0A、0x0E、0x11 不补发；心跳按低功耗规则恢复。
- 主机不因上传模式改变等待方式：仍等到 `T_exec_max` 再发获取结果。
