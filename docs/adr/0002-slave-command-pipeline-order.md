# 从机处理管线的判定顺序固定在框架内

从机对一帧的处理顺序固定为：① CRC 与帧尾失败 → 静默丢弃；② 地址不匹配 → 静默丢弃；③ 命令码未知或方向错误 → 0x04；④ 会话未建立且命令非 0x01 → 0x10；⑤ 载荷长度不符 → 0x02；⑥ **事务序号缓存命中 → 直接回放**；⑦ 长耗时命令执行中且该命令不允许并发 → 0x11；⑧ 参数校验失败 → 0x03；⑨ 执行 handler，其返回值即应答码。

这条管线只在框架里实现一次，handler 内部不得重复这些检查。

## Considered Options

- **每条命令各自决定检查顺序**：由板卡规范分别规定，最终每个板卡一套行为。
- **缓存命中放在 BUSY 判定之后**：看起来更“安全”，实际会错。

## Consequences

⑥ 必须在 ⑦ 之前。规范 5.2.8 要求“迟到的启动重传若命中缓存，从机回放已缓存应答，不得再次启动”；若先判 BUSY，重传会被回成 0x11，主机会误判为“被拒绝”而不是“已受理”。这是本顺序唯一一处依赖时序的条款，改它等于改协议语义。

新增任何拒绝条件都必须落到上述某一步，否则实现者无法预知同一帧命中多个条件时返回哪个应答码，测试向量也就写不出来。
