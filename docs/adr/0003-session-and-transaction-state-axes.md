# 主机状态分“会话”与“事务”两条正交轴

主机对每台从机维护两条互不折叠的轴：

- **会话状态**（长期，按从机计）：未连接、握手中、已握手、正常通信、版本不符、掉线；
- **事务状态**（短期，同一从机同时至多一个在途事务）：空闲、待发送、等待应答、等待结果。

重发次数是事务上的计数器（`attempt`）与累加后的 deadline，**不是**一个状态。

## Considered Options

- **单轴扩展**：把“等待应答”加进规范 §4.1.1 的观测状态表，成为第五个状态。已否决。
- **三轴**：再把“链路活性”单列一轴。已否决——掉线在本协议里必然导致会话失效（§6.2：恢复通信后执行重新握手），它属于会话轴的一个终态，单列会把同一事实表达两次。

## Consequences

否决单轴扩展的原因是三处硬伤：等待应答与正常通信互斥，会让状态在每次请求时来回抖动，回答不了“这台从机现在能否接收业务命令”；长耗时命令“已受理、等结果事件”无处安放；§7.2.1 的掉线判据是第三种时间尺度，继续往同一张表里塞会带来无法排除的非法组合。

对外的单个“设备状态”是展示层的组合渲染结果，不是协议状态。

规范需同步修订：§4.1.1 的表头由“观测状态”改为“会话状态”，并新增事务状态表；补齐 `版本不符`（§4.1.1(3) 现在只说“不得进入正常通信并报警”，未规定停在哪个状态）与 `掉线`。
