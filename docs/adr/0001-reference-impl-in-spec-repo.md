# 参考实现与协议规范同仓，分四层可裁剪

ECSP 的参考实现（C99、零动态分配）与规范正文放在同一个仓库：`include/ecsp/` 与 `src/ecsp/{core,slave,host}/`，测试在同仓 `test/`。实现按 L1 帧编解码、L2 通用命令编解码、L3 从机引擎、L4 主机链路管理四层切分，编译期可裁剪；板卡功能命令（0x30~0xEF）一律由使用方的编译期 `const` 命令表注入，库内不含任何板卡知识。

这个库的正确性定义就是规范正文。分仓之后“规范改了、实现没跟”会成为长期风险，而规范里已经明确会持续产出板卡实例（附录 E），参考实现留在同一处最省事。

## Considered Options

- **独立库仓库**：实现与文档解耦，但正确性定义割裂，规范变更无法与实现变更放进同一个 PR。
- **单文件库**：分发简单，但 L1~L4 无法独立裁剪，从机固件会被迫链接主机侧代码。
- **运行期注册命令表**：灵活，但把编译期错误推迟到运行期，且多占 RAM。命令表与地址分配本质是产品规范里的常量。

## Consequences

每次行为变更的 PR 必须是三件套：规范正文 diff + golden vector + 实现。只改代码会让 vector 退化成“实现快照”，追溯链断掉。
