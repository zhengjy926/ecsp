# 帧与载荷一律逐字节编解码，禁止结构体映射

帧结构、帧内字段与数据载荷全部用显式的小端读写助手（`rd_u16le` / `wr_u16le` / `rd_u32le` / `wr_u32le`、定长字符串拷贝）编解码。禁止把接收缓冲区强转为结构体、禁止 `#pragma pack`、禁止用指针别名读多字节字段。

三条独立的硬理由，任一条都足够否决结构体映射：帧字段顺序是“产品地址 → 命令码 → 板卡地址”，命令码夹在两个地址字段之间，导致后续字段跨字节边界不对齐；小端编码与大端目标、非对齐访问、严格别名规则三者叠加；数据载荷长度随命令可变，不可能用固定结构体表达。

## Consequences

解析器拿到的是字节窗口而不是结构体，读取载荷字段时按需解码并自行校验长度——这也让“载荷长度不符 → 0x02”这类判定能落在管线里而不是散在 handler 里（见 ADR-0002）。

字节级编解码顺带让大端目标天然可用，因此目标平台只剩 RAM 与 tick 位宽的预算问题，不再是移植性问题。
