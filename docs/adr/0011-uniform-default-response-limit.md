# 三类命令的默认应答时限同为 50 ms，主机不按命令类别等待

表 7-1 原来按命令类别分开：获取类 ≤50 ms，设置类与动作类 ≤100 ms，另有 0x03/0x05 的 3 s 和 0x0C 第一次应答的 500 ms。握手没有单独一行，主机借用动作类的 100 ms。

决定改为：获取类、设置类、动作类共用一个默认应答时限 50 ms，握手也是 50 ms。不再缩短到 50 ms 以下。已经写明更长上限的命令保持原值：0x03 与 0x05 为 3 s，0x0C 的第一次应答为 500 ms。0x07、0x08 的受理应答、0x0B、0x0F 用这 50 ms。

主机不用命令类别决定等多久。板卡命令表上写了应答时限的，主机用那个数；没写、或主机配置没带这张表的，用 50 ms。F429 的 0x32 与 0x33 仍是 100 ms，这个数要写在命令表上。命令类别仍只给定从机管线。

产品若放宽 0x07，只拉长 0x07。0x07 的应答时限单独保存，即便数值仍是 50 ms，也不与三类默认值绑成同一档。

## Considered Options

- **设置类和动作类维持 100 ms**：主机对沉默多等一倍才重发。正常命令并不会因此更快。否决。
- **默认值再降到 50 ms 以下**：从机组帧远远用不满 50 ms，再缩短会把还活着的从机判成不应答。否决。
- **主机继续用命令类别区分 50 ms 和 100 ms**：三类默认已经相同，类别读不出例外。否决。
- **放宽 0x07 时抬高整档 50 ms**：0x0B、0x0F 和 0x08 的受理应答会一起变长。否决。

## Consequences

- 规范表 7-1 与 7-4 改为三类同一个默认值，并写明单条命令的放宽不影响其它命令。
- F429 板卡规范里 0x32、0x33 的 100 ms 保留，作为命令表上的应答时限，不再解释成「设置类/动作类所以是 100 ms」。
- 从机命令表上的命令类别标志不参与主机的应答时限。
